# The FFI Build Pipeline

## 1. Why this chapter exists

The previous two chapters described both sides of the C ABI as source. This
chapter is the build machinery that connects them: how the Rust crate is compiled
into the `libzcashlc.xcframework` that `Package.swift` links, and how a
contributor swaps the released binary for a local build of their own `rust/`
changes. It answers: what generates the C header the Swift `import libzcashlc`
sees, what produces the static library inside the framework, and which script to
run after editing Rust. If you do not understand this, you can edit `rust/`, see
no change in Swift, and not know why (the answer is almost always a stale
artifact). By the end you can run `./Scripts/init-local-ffi.sh --macos-only` and
explain each artifact it produces.

## 2. Definitions

**Definition 2.1 (binary release mode).** The default. `Package.swift` declares a
`.binaryTarget` named `libzcashlc` whose `url` points at a pre-built
`libzcashlc.xcframework.zip` on a GitHub Release, validated by a `checksum`. No
Rust toolchain is needed; SPM downloads the framework. This is what clients of
the SDK get.

**Definition 2.2 (local FFI mode).** Active when `LocalPackages/Package.swift`
exists on disk. `Package.swift` detects the file and replaces the binary target
with a path dependency on `LocalPackages/`, which contains an XCFramework built
from your local `rust/`. Created by `./Scripts/init-local-ffi.sh`, removed by
`./Scripts/reset-local-ffi.sh` (which deletes `LocalPackages/`).

**Definition 2.3 (the generated artifacts).** Three files are generated at build
time and end up inside the framework or the crate:

- `target/Headers/zcashlc.h`: the C header, generated by cbindgen from the Rust
  source. This is what `import libzcashlc` exposes to Swift.
- `$OUT_DIR/bindings.rs`: Rust bindings for the Apple `os_log` / `os_signpost` C
  functions, generated by bindgen from `rust/wrapper.h`.
- `libwrapper.a`: a small C object compiled by the `cc` crate from
  `rust/wrapper.c`, linked into the crate (it provides the `os_log_*` shims that
  `bindings.rs` declares).

## 3. The code

### build.rs: bindgen, cc, cbindgen

The crate build script runs all three generators. First the rerun triggers and
the bindgen block:

```rust reference title="rust/build.rs"
https://github.com/zcash/zcash-swift-wallet-sdk/blob/fe836893bc71fc3e6eb173f4fc191aa43c3760af/rust/build.rs#L5-L24
```

`bindgen::builder().header("rust/wrapper.h")` reads the Apple logging header
([rust/wrapper.h](https://github.com/zcash/zcash-swift-wallet-sdk/blob/fe836893bc71fc3e6eb173f4fc191aa43c3760af/rust/wrapper.h)),
allowlists only the `os_log_*`, `os_release`, and `os_signpost_*` functions, and
writes Rust declarations to `$OUT_DIR/bindings.rs`. This is the inbound
direction: C to Rust.

The `cc` step compiles the C shim that backs those declarations:

```rust reference title="rust/build.rs"
https://github.com/zcash/zcash-swift-wallet-sdk/blob/fe836893bc71fc3e6eb173f4fc191aa43c3760af/rust/build.rs#L26-L26
```

`cc::Build::new().file("rust/wrapper.c").compile("wrapper")` produces
`libwrapper.a` and links it into the crate.

The cbindgen block is the outbound direction (Rust to C) that produces the header
Swift consumes:

```rust reference title="rust/build.rs"
https://github.com/zcash/zcash-swift-wallet-sdk/blob/fe836893bc71fc3e6eb173f4fc191aa43c3760af/rust/build.rs#L30-L75
```

cbindgen scans the crate for `#[repr(C)]` types and `extern "C"` functions and
emits a C header. The chain of `.rename_item(...)` calls is why the Rust type
`Account` (from `rust/src/ffi.rs`, seen in
[the FFI surface chapter](./03-rust-core-ffi-surface.md)) appears in the header
and in Swift as `FfiAccount`: cbindgen renames `Account` to `FfiAccount`,
`Uuid` to `FfiUuid`, `BinaryKey` to `FFIBinaryKey`, and so on. The header is
written with `b.write_to_file("target/Headers/zcashlc.h")` (L74). The whole
cbindgen call is wrapped in `if let Ok(b) = ...`, so a cbindgen failure is
ignored rather than failing the build.

### Package.swift: detecting the mode

`Package.swift` decides which target to use by checking for the
`LocalPackages/Package.swift` marker, then branches:

```swift reference title="Package.swift"
https://github.com/zcash/zcash-swift-wallet-sdk/blob/fe836893bc71fc3e6eb173f4fc191aa43c3760af/Package.swift#L5-L38
```

`useLocalFFI` is the marker check (L10). When true, it adds a path dependency on
`LocalPackages/` (L24-L26). When false, it appends the `.binaryTarget` with the
release `url` and `checksum` (L30-L36). The comment at L29 notes the URL and
checksum are updated by `Scripts/release.sh` at release time.

### init-local-ffi.sh: the --macos-only path

The setup script has three paths. The default builds all slices through
`BuildSupport/Makefile`; `--cached` downloads the release zip and verifies its
checksum; `--macos-only` builds just the macOS slice for fast `swift build` /
`swift test` on the Mac:

```bash reference title="Scripts/init-local-ffi.sh"
https://github.com/zcash/zcash-swift-wallet-sdk/blob/fe836893bc71fc3e6eb173f4fc191aa43c3760af/Scripts/init-local-ffi.sh#L29-L36
```

The `--macos-only` branch (L31-L36) creates `LocalPackages/`, creates the
XCFramework directory, and delegates to `./Scripts/rebuild-local-ffi.sh macos`.
After any path, the script copies `BuildSupport/LocalPackages-Package.swift` to
`LocalPackages/Package.swift`
([Scripts/init-local-ffi.sh L88](https://github.com/zcash/zcash-swift-wallet-sdk/blob/fe836893bc71fc3e6eb173f4fc191aa43c3760af/Scripts/init-local-ffi.sh#L88));
that file is the marker `Package.swift` checks for.

`rebuild-local-ffi.sh` does the incremental single-arch build. For `macos` it
selects the Rust triple by host architecture and the matching XCFramework slice
name:

```bash reference title="Scripts/rebuild-local-ffi.sh"
https://github.com/zcash/zcash-swift-wallet-sdk/blob/fe836893bc71fc3e6eb173f4fc191aa43c3760af/Scripts/rebuild-local-ffi.sh#L61-L72
```

It then runs `cargo build --target "$RUST_TARGET" --release`
([Scripts/rebuild-local-ffi.sh L95-L100](https://github.com/zcash/zcash-swift-wallet-sdk/blob/fe836893bc71fc3e6eb173f4fc191aa43c3760af/Scripts/rebuild-local-ffi.sh#L95-L100))
to produce `libzcashlc.a`, copies `target/Headers` (the cbindgen output) and
`BuildSupport/module.modulemap` into a single-slice framework, and atomically
replaces the XCFramework so no stale slice from another platform remains.

The full multi-arch build (the default `init-local-ffi.sh` path) is the
`BuildSupport/Makefile` `xcframework` target, which lipo-combines per-arch static
libraries into universal libraries, wraps each in a `.framework` with the shared
`target/Headers`, and assembles the three platform slices
([BuildSupport/Makefile L34-L57](https://github.com/zcash/zcash-swift-wallet-sdk/blob/fe836893bc71fc3e6eb173f4fc191aa43c3760af/BuildSupport/Makefile#L34-L57)).

### reset-local-ffi.sh: back to the binary

```bash reference title="Scripts/reset-local-ffi.sh"
https://github.com/zcash/zcash-swift-wallet-sdk/blob/fe836893bc71fc3e6eb173f4fc191aa43c3760af/Scripts/reset-local-ffi.sh#L8-L16
```

It removes `LocalPackages/` so `useLocalFFI` becomes false, and reminds you that
Xcode may need File > Packages > Reset Package Caches to drop the cached path
dependency.

## 4. Failure modes

- Editing `rust/` while in local FFI mode but not rebuilding, or rebuilding only
  one arch and then having Xcode switch platforms. The framework still carries
  the old code, so Swift behaviour does not change. `rebuild-local-ffi.sh`
  atomically replaces the XCFramework with a single slice to make this loud
  rather than silent, but you must rerun it for each target you build. No
  automated test in this workspace; caught by audit only.
- Switching modes (running `reset-local-ffi.sh` or `init-local-ffi.sh`) without
  resetting Xcode's package caches, so Xcode links a stale header from the old
  target and Swift sees mismatched type names (for example missing `FfiAccount`).
  The fix is Cmd+Shift+K then File > Packages > Reset Package Caches, as the
  reset script prints. No automated test in this workspace; caught by audit only.
- Opening a PR that changes the FFI boundary (a new `zcashlc_*` function or a
  changed `#[repr(C)]` type) after rebuilding only the simulator slice with
  `rebuild-local-ffi.sh`. The released XCFramework the PR will ship is produced
  by the full multi-arch build, so a single-arch local build can hide a
  per-platform breakage. Run the full `./Scripts/init-local-ffi.sh` before
  PRing. Caught by: the `Build FFI XCFramework` workflow
  ([.github/workflows/build-ffi.yml](https://github.com/zcash/zcash-swift-wallet-sdk/blob/fe836893bc71fc3e6eb173f4fc191aa43c3760af/.github/workflows/build-ffi.yml)),
  which builds all slices on `macos-15`, though it is `workflow_dispatch` (manual)
  rather than per-PR.

## 5. Spec pointers

- `docs/LOCAL_DEVELOPMENT.md` in this repo is the full reference for the local
  FFI workflow these scripts implement; read it for the Xcode workspace setup
  (`ZcashSDK.xcworkspace`) that auto-runs the rebuild.
- cbindgen (https://github.com/mozilla/cbindgen): generates `zcashlc.h` from the
  Rust source; the `rename_item` API is what produces the `Ffi*` names Swift
  uses.
- bindgen (https://github.com/rust-lang/rust-bindgen): generates `bindings.rs`
  for the Apple `os_log` functions in `rust/wrapper.h`.
- Swift Package binary targets
  (https://developer.apple.com/documentation/packagedescription/target/binarytarget(name:url:checksum:)):
  documents the `url` + `checksum` `.binaryTarget` form used in binary release
  mode.
- [The build, test, and contribution loop](./02-build-test-contribution-loop.md)
  for where these scripts sit in day-to-day work, and
  [the Rust core and the FFI surface](./03-rust-core-ffi-surface.md) for the
  source that cbindgen turns into the header.
